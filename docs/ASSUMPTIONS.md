## Phase 6

| # | Assumption | Rationale |
|---|---|---|
| 60 | `runInWorker` runs the engine on a real `worker_threads` worker (entry `./worker.ts` under `tsx`, `./worker.js` in `dist/`), with `timeout = max(1000, timeBudgetMs) + 5000` → structured `TIMEOUT`, and **inline fallback** to `generateSeating` if the thread cannot start or crashes. Supersedes assumption 52. | Guide §7 requires the Express event loop to stay responsive; a threading problem must degrade to a correct inline run, never to a fake failure (Rule 5). |
| 61 | Local-search budget = **min(20·N, 30 000) iterations** *and* a deadline of **min(remaining timeBudget, 2 000 ms)**, per guide §4.3's "e.g. max 2 s or 20·N iterations". The 30k clamp is what keeps a 5,000-student generation's search phase inside ~1 s so the `< 2000 ms` engine test passes with margin. | Sanctioned by the guide text; both a time and an iteration bound were requested. Gains flatten out long before 20·N at large N (verified: identical final penalty at 30k and 50k iterations). |
| 62 | `swapDelta` is **exact**: both students' penalties at each other's seats (occupant override) plus neighbour-history/department/roll deltas for the at-most-four students beside their old/new seats, honouring the same-seat precedence rule. `improve` caches each student's penalty and refreshes only the six possibly-affected seats after an accepted swap, so rejected swaps (the common case) skip full re-evaluation. | Verified by a 3 000-swap brute-force equality check against full rescoring; caching cannot drift because every changed student is refreshed. |
| 63 | The imbalance term `λ·variance(fill%)·100` is computed over **selected rooms only** and enters greedy candidate scoring as an O(1) marginal delta; `swapDelta` omits it because a swap never changes room loads. | Correctness (it is swap-invariant) plus speed (no per-candidate full recomputation). |
| 64 | `maxPerDepartment` is a **per-room** cap with three enforcement points: feasibility fails `DEPARTMENT_RULE_IMPOSSIBLE` (details: `{departmentId, students, maxPerDepartment, reachable}`) when unattainable; construction enforces it best-effort with a full-pool fallback; `improve` re-checks cross-room swaps before accepting. BLOCK swaps are restricted to same-department pairs. | Guide calls it a soft rule, but an unattainable cap must fail loudly rather than silently violate (Rule 5); contiguity must survive local search. |
| 65 | `sameDeptAdjacent` is penalised only in MIXED mode (in BLOCK, department contiguity is the goal); `stats.sameDeptAdjacent` counts adjacent same-department bench pairs in the final arrangement. | Guide §4.4 mixes departments by penalising adjacency; BLOCK inverts the objective. |
| 66 | `stats.*` count repeats against the **most recent** previous paper only (d = 1); equal bench numbers count even across rooms; a same-seat hit short-circuits that paper's other events. | Matches the dashboard wording ("vs previous paper") and guide §4.4's same-seat precedence. |
| 67 | Disabled seats are excluded from capacity, adjacency maps and allocation; a room whose seats are **all** disabled counts as unavailable (`NO_AVAILABLE_ROOMS`), partial disabling just reduces capacity. | Consistent seat semantics everywhere (feasibility, allocation, validation). |
| 68 | Greedy construction details: students ordered hardest-first (previous-paper count desc), rooms ordered (seeded shuffle → usage asc → size desc), smallest sufficient room first, K = 16 sampled candidate seats per student (more early on) scored by `penaltyAt + marginal imbalance`, BLOCK claims contiguous bench runs and spills to a global pool when a run fills. | Guide §4.3 steps 2–4; deterministic under the seed. |
| 69 | The independent validator caps `violations` at 50 entries; `generateSeating` returns `VALIDATION_FAILED` (report in `details`) whenever it reports INVALID — a plan is never returned, never mind saved (Rule 5). | Defence in depth: the validator shares no code paths with the constructor's own checks. |
| 70 | `docs/ALGORITHM.md` carries the real pseudocode, benchmarks (10/100/1000/5000 measured, best of 5) and the full `npm run demo:algorithm` output; the demo prints engine `stats` plus plain-English per-student history explanations. | Guide §4.6 deliverables. |

| 89 | Roll numbers follow **`SE-AIDS-C_07`** = year code (`FE`/`SE`/`TE`/`BE`) – branch code – division letter(s) – serial. Branch codes are constrained to `[A-Z]{2,6}` so they always fit the roll grammar (hence `ETC`, not `E&TC`). | Confirmed by the college. |
| 90 | **No `Cohort` (admission-year) field.** A student is promoted `SE` → `TE` → `BE`, so only one cohort occupies each year code at a time and roll numbers are already unique. | Confirmed by the college; removes a whole entity that would otherwise have to be added to every query. |
| 91 | Roll **ranges are stored as parsed components** (`yearCode`, `branchCode`, `division`, `fromSerial`, `toSerial`), never as raw roll strings, and compared numerically. | A string comparison mis-orders zero-padded serials: `"SE-CE-A_99"` sorts *after* `"SE-CE-A_100"`, which would silently mis-seat a division of 100+. |
| 92 | Serials zero-pad to a **minimum of two digits** (`_07`); three-digit serials are written unpadded (`_100`). | Matches the college's written convention. |
| 93 | Division is an administrator-supplied **A-Z letter**, validated `^[A-Z]{1,2}$` and upper-cased rather than rejected, so typing `c` yields `C`. | Confirmed: "Division input is given in A-Z format". |
| 94 | The unit of allocation is an **AllocationIntent** ("roll range → room") declared per exam, and generation executes those intents instead of searching the whole building. `seatOffset` and an optional `rows × cols` grid place the block inside a room; omitting the offset auto-advances to the next free bench window. | This is what the college asked for: the administrator chooses which room a range sits in. The engine still shuffles *within* the chosen room so the "don't repeat the last allocation" rule holds. |
| 95 | Each intent is an **independent sub-plan** with its own students, room, bench window and history; the merged plan is then validated as a whole before anything is saved. | Keeps "don't repeat the last paper" meaningful inside the block the administrator defined, while still catching cross-block violations. |
| 96 | `config.strictRollOrder` seats a block in ascending roll order and **skips the local-search phase entirely**. Penalties are still reported. | Any swap would undo the ordering; the administrator asked for an invigilator-friendly, readable order. |
| 97 | Room numbers are globally unique and floor-prefixed (`101` = 1st floor, `201` = 2nd), so the existing unique constraint on `classroom.room_number` is kept as-is. | Confirmed: room numbers do not repeat across floors. |
| 98 | The system is **administrator-only**. The `STUDENT` role is removed from the `user_role` enum (rebuilt, since PostgreSQL has no `ALTER TYPE … DROP VALUE`), the `/me` portal and slip endpoints are deleted, students get no login accounts, and roll number is not a login identifier. | Confirmed: "only administrator, no student login". |
| 99 | The SPPU curriculum (`Subject`, `Department.sanctionedIntake`) is **reference data only** — it never drives seating, and the parsers degrade gracefully rather than failing on an odd row. | Seating is driven by exam + intents. A curriculum typo must never block running an exam. |
